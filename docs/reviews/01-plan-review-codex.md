以下只依提供的文件審查；套件版本、模型來源與授權敘述尚未獨立查證。整體架構可行，但目前還不能保證各硬體等級都能提供「即時字幕」，也不能只靠禁用名單保證模型來源合規。

1. **[blocker] 各等級缺少可驗收的延遲目標，校正方式也無法代表實際負載。**  
   **問題：** `cpu-high` 關閉 partial，連續說話時可能等約 8 秒才送 final，再加解碼與翻譯時間；以文件中的 small CPU 測量作參考，字幕可能十秒左右才出現。Intel turbo 每 1.5 秒排一次、單次解碼也約 1.5 秒，幾乎沒有 final、其他程式或散熱降頻的餘裕。5 秒 TTS 單次解碼通過，不代表連續重解能跟得上。  
   **建議：** 分別定義「首個原文 partial」「語音結束至 final」「目標語言字幕」的 p50／p95 延遲與最大積欠時間。校正改用持續說話、短句及停頓混合的錄音，跑完整 pipeline；依結果獨立調整模型、partial 間隔與切段長度。CPU 無法達標時，應明示為「分段字幕」模式。

2. **[major] final 優先只處理排隊順序，無法搶占正在執行的 partial。**  
   **問題：** final 可能被剛開始的長 partial 阻塞；忙碌時覆蓋 partial 也無法避免 final 積欠。舊 partial 還可能晚於 final 抵達，把已確認字幕改回暫定文字。  
   **建議：** 每個請求帶 `session_id、segment_id、revision、audio_end_sample`。final 確認後拒收該段所有 partial；partial 採單一待處理槽，final 佇列設容量及過載處理。依近期推論耗時自動降低 partial 頻率，並明確量測正在執行的 partial 對 final 的阻塞時間。

3. **[major] partial 的穩定性策略沒有定義。**  
   **問題：** 每次重解整段都可能改寫前文；文件引用 LocalAgreement，但設計沒有穩定前綴或可修改範圍。字幕可能每 0.6 秒整行跳動。  
   **建議：** 明訂「穩定前綴＋可修改尾端」的顯示契約。可採連續兩次假設的共同前綴，但需定義 final 如何修正；如果 MVP 暫不做穩定提交，至少只替換當前 partial 區域，固定先前 final 的內容與位置。

4. **[major] 強制切段可能切在音節中間，也缺少跨段銜接資訊。**  
   **問題：** 最後 1.5 秒的最低 VAD 機率，不一定代表停頓；連續說話時可能每個位置都是語音。直接拆開會造成漏字、重字與翻譯語意斷裂。目前 ASR 回傳值沒有時間戳，難以可靠處理重疊。  
   **建議：** 優先找滿足門檻與最短長度的低語音區間；找不到時使用有上限的硬切，保留少量重疊及絕對樣本位置。ASR 介面增加可選的 segment／word timestamps 與能力標記，設計跨段對齊去重。將「音訊區塊完成」與「語句完整」分開，翻譯另設等待上限。

5. **[major] 丟棄短於 0.35 秒的語音會漏掉有效短句。**  
   **問題：** 「好」「對」「No」都是合理字幕，不能只憑時長當作雜音。開始條件、pre-roll、句尾靜音及強制切段的交互行為也尚未完整定義。  
   **建議：** 短音段改由語音信心、能量及辨識結果共同判斷，避免一律丟棄；以樣本數定義邊界及 pre-roll 所有權，測試短答覆、快速接話、切段後立即停頓與同批音訊內多次 start／end。

6. **[blocker] 以整句二分語言，無法滿足中英夾雜與「只顯示中文／英文」。**  
   **問題：** 例如「這個 API uses a cache」被判為 zh 後，中文模式會直接顯示英文片段；反過來也一樣。第一個 partial 判成英文就鎖定語言，還可能影響後續中文辨識。  
   **建議：** 分開保存「ASR 語言提示」「文字語言組成」「顯示目標語言」。允許 `mixed／unknown`，不要讓首次短 partial 的判斷成為不可更改的鎖定。混合文字需經驗證可處理混合輸入的翻譯路徑，或以片段轉換後重組；若預設模型做不到，必須明訂 MVP 限制，不能把混合原文當作已完成的中文或英文版本。

7. **[major] prompt 與 OpenCC 規則可能改變英文辨識及原文內容。**  
   **問題：** 所有輸入都加繁中提示，可能對英文或語言自動判斷產生偏向；150「字」也不是模型的 token 預算。`s2twp` 涉及詞彙轉換，與使用者理解的「原文」不完全相同。  
   **建議：** 依來源設定選用提示，以各後端 tokenizer 限制長度；長停頓、切換語言、裝置或工作階段時清除上下文。保留 raw transcript，另外產生顯示正規化版本；將台灣用語轉換列為明確設定。用 A/B 測試確認提示是否確實改善繁中且不傷害英文。

8. **[major] 幻覺過濾與重複截斷會刪掉正常發言。**  
   **問題：** 「Thank you.」和「謝謝觀看」可能就是講者說的話；重複字詞也可能是強調、口吃或逐字拼讀。全段相似度門檻無法提供足夠證據。提高 `no_speech_threshold` 也不能直接等同更強的幻覺過濾。  
   **建議：** 將清單降為可疑訊號，結合 VAD 覆蓋率、音訊特徵及後端實際提供的信心資訊才決定是否隱藏。重複處理優先針對已知解碼迴圈，保留 raw text 與過濾原因，加入正常致謝及合理重複的反例測試。

9. **[major] ASR 共用介面假設兩個後端提供相同能力。**  
   **問題：** 文件未證明 OpenVINO 提供與 faster-whisper 同義的 `avg_logprob、no_speech_prob`、prompt、語言偵測及解碼設定。若以假值補欄位，過濾會產生錯誤結果。  
   **建議：** 建立後端能力表及契約測試；不支援的指標回傳 `None`，由處理層明確跳過相關規則。逐項驗證語言、prompt、時間戳及模型相容性，避免宣稱後端行為完全一致。

10. **[major] 翻譯佇列及字幕生命週期尚未閉合。**  
    **問題：** `line_id` 能對應字幕，卻不能防止停止後回填、工作階段 ID 重用或已淘汰字幕重新出現。慢速 Ollama 也可能持續處理早已看不到的文字。只翻 final 表示目標語言的即時性仍受切段時間限制。  
    **建議：** 翻譯請求帶工作階段、行 ID、版本與期限；回填時驗證字幕仍存在且版本吻合。設定有限佇列、timeout、過期淘汰與錯誤狀態。中文／英文限定模式應預設顯示最近有效目標字幕或等待狀態，原文暫代須是明確選項。

11. **[major] CaptionBoard 的狀態擁有者與停止流程未定義。**  
    **問題：** ASR、翻譯及 UI 都可能同時改變字幕。queued signal 只解決 UI 投遞，不會自動保護核心共享資料。模型載入或 worker 結束若在主執行緒等待，也會卡住面板。  
    **建議：** 由單一協調執行緒擁有 CaptionBoard，其他 worker 只送不可變事件；Qt 只接收畫面快照。明訂 starting／running／stopping／failed 狀態，停止時失效化舊請求、停止收音、清空待處理工作，並在非 UI 執行緒等待 worker。

12. **[major] 音訊 callback 與資源競爭缺少限制。**  
    **問題：** 「放進 queue」若會阻塞，仍會造成音訊遺失；若未複製 callback buffer，可能讀到被重用的資料。ASR、翻譯與 ONNX Runtime 的內部執行緒也可能共同塞滿 CPU；NVIDIA ASR 與翻譯則會競爭 GPU。  
    **建議：** callback 使用獨立資料副本與非阻塞、有限容量的緩衝區；溢位記錄為音訊不連續事件並重設相關狀態。明訂單聲道 16 kHz 浮點音訊契約與有狀態重採樣。配置各引擎執行緒預算，GPU 共用則採資源仲裁或先讓翻譯走 CPU。

13. **[major] Qt 視窗旗標不足以保證 Windows 多螢幕行為。**  
    **問題：** 目前未規範 DPI 單位、負座標螢幕、工作區與全螢幕幾何、拔除螢幕及縮放切換。切換旗標也可能重建原生視窗。`Tool＋置頂＋點擊穿透` 仍需驗證焦點與實際呈現行為。  
    **建議：** 將 UI 尺寸明訂為 Qt 邏輯像素，區分字型 point／pixel 單位；使用選定螢幕的 geometry 或 availableGeometry 並定義取捨。監聽螢幕增減、幾何與 DPI 變更，失去螢幕時回主螢幕。設定不搶焦點，實測不同縮放比例、左右負座標、全螢幕簡報及 click-through。

14. **[major] 固定高度沒有定義長字幕與雙語的排版上限。**  
    **問題：** `max_lines` 指的是句子，但一句可能折成多個視覺行；雙語再加倍，96 px 字體時容易裁切。譯文回填亦可能推動已顯示內容。「譯文縮小」在中英固定排序下也有歧義。  
    **建議：** 分開定義保留句數、每句最多視覺行及總顯示高度；預留雙語欄位，制定折行、溢出與淘汰規則。明訂次要字體是跟隨語言、原文或譯文，並驗證最長文字、最大字體與最小螢幕的組合。

15. **[major] 隱藏控制與狀態 UX 還缺少失敗時的回復方式。**  
    **問題：** 360×520 對「小型控制面板」偏大；熱鍵註冊可能失敗，系統匣也可能不可用。六秒清除若只從 final 計時，可能在下一句仍有 partial 或等待翻譯時淡出。  
    **建議：** 提供只含開始／停止、狀態及隱藏的精簡面板，其他選項放展開區。檢查熱鍵與系統匣可用性，至少保留一條可驗證的面板恢復路徑。清除計時納入最近語音活動與有效更新；明示載入、暖機、收音、無裝置、翻譯失敗及回退狀態。設定寫入採 debounce 與原子替換。

16. **[major] 硬體名稱不能代表推論後端可用，偵測流程也有循環依賴。**  
    **問題：** 安裝 OpenVINO 前無法確認它是否看得到 GPU；`nvidia-smi` 存在也不代表 CT2 能成功載入。VRAM 總量未考慮可用記憶體、GPU 支援能力及多張 GPU；標準函式庫本身也沒有跨平台實體核心數介面。  
    **建議：** 分成「標準工具粗篩候選後端」與「安裝後實際載入、短推論探測」兩階段。明確選定裝置、記錄探測失敗原因，系統指令設 timeout；缺少資訊時保守降級。CPU 核心數採各平台明確實作，無法取得時回傳 unknown。

17. **[blocker] 「自動降一級」及離線回退沒有可執行的完整路徑。**  
    **問題：** 等級表不是單一效能序列；Intel turbo 降級可能應先改 Intel small，而非換到另一廠牌或直接 CPU。NVIDIA 失敗一律退 `cpu-high` 也不符合所有機器。若回退模型未下載，斷網時就無法回退。  
    **建議：** 為每個 profile 建立明確 fallback graph，涵蓋初始化失敗、OOM、驅動問題及推論過慢。安裝時下載並驗證可用的 CPU 保底模型與相依套件，依 CPU 能力選擇；實際跑一次離線回退測試。手動 profile 應與實際採用 profile 分別記錄。

18. **[major] Windows 安裝與 DLL 載入仍是未驗證的交付風險。**  
    **問題：** `none` 不是天然有效的 extra；bootstrap Python、支援版本與 wheel 架構尚未固定。CUDA wheel、CT2、cuDNN 與驅動須整組驗證，且 DLL 搜尋路徑必須在原生程式庫載入前建立並維持有效。只接受 numpy 輸入，也未解決 `FileSource` 的檔案解碼相容性。  
    **建議：** `none` 分支使用不帶 extra 的安裝命令，固定 Python 與 lockfile，驗證 Windows x64 的完整相依版本組合。保留 `os.add_dll_directory` handle 至程式結束，加入實際推論 smoke test。捷徑直接啟動已安裝環境，避免正常啟動觸發同步或下載；另外固定 WAV 讀取路徑，測試中文及含空白路徑、無管理員權限與安裝中斷重試。

19. **[blocker] 模型禁用名單不足以執行來源硬限制。**  
    **問題：** repo 名稱、轉檔者所在地及 alias 都不能證明模型的完整來源；Ollama tag 也不能固定實際權重。文件中的「上傳者在台灣」與「MIT／Apache」不足以作為來源及授權證據。  
    **建議：** 使用經審查的 allowlist manifest，記錄原始開發者、基底與衍生關係、轉檔者、來源證據、精確 revision／digest、檔案雜湊及授權文件。先明訂「中國資本來源」適用的判準，證據不完整就不納入自動安裝。測試應拒絕未登錄模型與未固定版本；來源審查本身仍需人工完成。

20. **[major] 授權與離線完整性缺少交付規格。**  
    **問題：** quickmt 的署名義務、選用模型各自條款，以及 PySide6／Qt 的散布義務，都尚未落到產品。快取存在也不等於可離線：tokenizer、設定檔、VAD 資產或選用模型可能仍缺少。  
    **建議：** 建立模型與套件授權清單，隨安裝包提供必要的署名、授權及 notices；對每個模型分別確認權重與基底條款。下載採暫存、完整性驗證後才啟用，保存資產 manifest。驗收應在封鎖網路下涵蓋首次啟動、重啟、正常推論及回退。

21. **[major] 測試目前偏向功能正確，缺少時間、競態與真實平台驗收。**  
    **問題：** TTS 太乾淨，offscreen 無法驗證 Windows 穿透、焦點、熱鍵與 DPI；「不拋例外」也抓不到舊字幕復活、延遲無限增加或文字被誤刪。  
    **建議：** 注入假時鐘與可控制完成順序的 ASR／翻譯，測試 final 先到、舊 partial 晚到、停止再開始、佇列溢位及字幕淘汰。加入真人台灣華語、英文、中英夾雜、短答覆、長連講與背景噪音資料，量測 CER／WER、漏字及端到端 p95 延遲。實機矩陣涵蓋各後端、乾淨 Windows 安裝、混合 DPI、拔插裝置與斷網；長時間測試需斷言記憶體和積欠量有界。

值得保留的設計：

- **核心不依賴 Qt，搭配可替換 ASR／翻譯介面**，利於測試與後端演進。
- **單一 ASR worker、過時 partial 覆蓋、翻譯只處理確認文字**，方向合理，補齊生命週期與容量限制即可。
- **Intel 內顯獨立使用 OpenVINO，並以本機量測選擇方案**，比只看硬體名稱可靠。
- **固定字幕區域、描邊／底框、螢幕選擇、系統匣與熱鍵**，符合演講字幕的主要需求。
- **預先下載、離線執行與模型 registry**，值得維持，並強化成可驗證的完整交付流程。
