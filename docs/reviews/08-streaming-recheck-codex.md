# 複審：邊講邊出字修正

## 結論（需修正）

共用引擎的排程與跨句 partial 顯示已正確修正；仍有 **setup 背景推論失敗卻通過校正**的阻擋問題，以及取消路徑的語言快取清理缺口。

本次僅依內嵌內容靜態審查，未執行測試；266 + 4 通過及效能數據視為提供的實測結果。

## 新發現

### 1. major — 校正的 partial 執行緒失敗或逾時，仍可採用該等級

**位置：** `src/livesub/setup_cli.py:169–190、230–231`（依 diff 新檔行號）

**情境：** partial 暖機成功，但開始與 final 並行後拋出例外。`keep_partial_busy()` 沒有捕捉並回傳錯誤，主執行緒的 `try` 不會收到子執行緒例外；若沒有成功樣本，`partial_s` 不存在，`choose()` 以 `r.get("partial_s", 0)` 當成零秒通過。若先成功一次再失敗，也可能靠既有樣本通過。

`join(timeout=10)` 後亦未檢查執行緒是否仍存活，卡住的 partial 可在校正回傳後繼續占用 GPU，干擾後續工作。

**修法：** 將背景錯誤、完成狀態及樣本數明確回傳；獨立 partial 必須有有效樣本、沒有例外且 worker 已結束才可通過。逾時應判定失敗，並避免在舊推論仍執行時繼續載入下一級。新增「暖機成功、並行時失敗」及逾時測試。

### 2. minor — 並行校正沒有保證量到有效重疊

**位置：** `src/livesub/setup_cli.py:169–190`；`tests/test_setup_cli.py:35`

**情境：** `th.start()` 不保證 partial 已開始推論，final 就可能完成兩輪；partial 中位數也混入未與 final 重疊的樣本。現有假引擎立即回傳固定 `seconds`，`calls >= 2` 只能證明呼叫次數，不能證明並行負載。

**修法：** 加入啟動同步與推論起訖紀錄，只採用符合重疊條件的量測；測試用 Event 控制兩引擎同時執行，並驗證「單獨通過、並行超標」會降級。

### 3. minor — 取消與 final 失敗仍會留下或復活語言快取

**位置：** `src/livesub/core/pipeline.py:454–456、535–540、592–604、675–676`

**情境：** partial 正在推論時，該句被取消或 final 拋出例外；目前只封鎖字幕板，沒有清除或封鎖 `utt_lang`。晚到 partial 的 utt 仍可能大於 `max_final_utt`，因此重新寫入已結束句子的語言。連續只有取消而沒有成功 final 時，也不會執行快取大小清理。

字幕板會拒收結果，因此此處不是字幕復活，但 06-7 的語言快取契約尚未完整成立。

**修法：** 對取消、丟棄與 final 失敗統一執行語言快取終止處理，在 `ctx_lock` 下清除並記錄該 utt 已結束；不能直接推進最大編號而誤封仍在執行的較舊句子。補上受控完成順序測試。

### 4. minor — 新相似度會把極短的錯誤輸出判為滿分

**位置：** `src/livesub/setup_cli.py:106–127`

**情境：** 五秒音訊若異常地只輸出「的」或「大家好」，因全部字都出現在預期文字中，`matched / len(got)` 仍為 `1.0`，且非空檢查也通過。新指標解決完整參考句與截斷音訊不一致，卻失去了對嚴重漏字的辨識能力。

**修法：** 保留輸出正確比例之外，加入對應音訊的最低覆蓋要求；較可靠的方式是使用文字與長度已知的固定校正音檔。新增極短合法字串不得通過的測試。
